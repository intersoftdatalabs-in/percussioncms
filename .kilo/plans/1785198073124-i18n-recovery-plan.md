# i18n Recovery Plan: Inline Translations, Full OOB Locale Matrix

## 1. Current state (read-only audit summary)

Branch: `feature/i18n-additional-locales` (cleaned on top of `development`).
Branch-only files: **67**, +178,554/-3,018 lines across `modules/perc-i18n`, `rest`, and `WebUI`.

### 1.1 Canonical TMX (current behaviour)

- `modules/perc-i18n/src/main/resources/i18n/CmsUi.tmx` (18,460 lines): **1,635 real `<tu>`s**, 1,636 en-us / 1,633 es / **750 hi** `<tuv>`s, 9 duplicate tuids, `xml:lang="e"` typo at line 2824, raw `&` in `tuid` at line 18261.
- `modules/perc-i18n/src/main/resources/i18n/SystemResources.tmx` (4,738 lines): **636 `<tu>`s**, 636 en-us, only **10 es** `<tuv>`s, **0 hi**, 2 duplicate tuids.
- `modules/perc-i18n/src/main/resources/i18n/ResourceBundle.tmx`: empty body, single `en-us` header.
- `CmsUi` is the only file **parsed by a path** — `PSTmxResourceBundle.loadResources` reads `rxconfig/I18n/ResourceBundle.tmx` plus `sys_resources/I18n/` and `rx_resources/I18n/`; `CmsUi`/`SystemResources` are *not* loaded by the runtime (they are extracted to `rxconfig/i18n/` by `perc-distribution-tree/pom.xml:507-525` and consumed by the JSP `tmx.jsp` via `PSTmxResourceBundle`, which only reads the directory tree files; verify the live load step before relying on the inline merge).

### 1.2 Branch additions — three categories

1. **15 per-locale `*.tmx` files** (`en_US.tmx`…`tr_TR.tmx`, plus `ja-JP.tmx`): each ~2,175 keys. Only `de_DE.tmx` has actual translations (~2,075 different segs vs English); 14 others are English copies relabelled with non-canonical language tags (`US`, `GB`, `DE`, `CL`, `es_ES`, `fr_FR`, …) and the `xml:lang` attribute. `de_DE.tmx`, `en_US.tmx`, `en_GB.tmx`, `es_CL.tmx` are not XML-well-formed (raw `<{n}>` placeholders) and would be rejected by `PSTmxResourceBundle.addResourcesToCache` at parse time. The 15 files are also not picked up by the runtime because they sit in `rxconfig/i18n/`, not in `sys_resources/I18n/` or `rx_resources/I18n/`.
2. **Two salvageable backups**: `modules/perc-i18n/src/main/resources/i18n/backup/hi.tmx` (2,175 TUs, real Hindi) and `backup/es.tmx` (2,175 TUs, real Spanish). 880 CmsUi keys and 624 SystemResources keys can be salvaged from `backup/hi.tmx`; 2 CmsUi keys and 624 SystemResources keys from `backup/es.tmx`. Both would be shipped inside the JAR because nothing excludes them.
3. **17 sandbox / debug `test_*.tmx`**, `__pycache__/*.pyc`, and 8 broken Python/shell generators referencing nonexistent filenames and `trans` (the Docker tool). All 8 scripts would be packaged as resources.
4. **REST/WebUI experiment** (commit `c09c1e2f1b`): `rest/src/main/java/com/percussion/rest/i18n/{I18nResource,I18nAdaptor,II18nAdaptor,Translations,ErrorResponse}.java` and `WebUI/src/main/ts/i18n/{api,useTranslations,index}.ts` (430 lines). No consumers, no tests, breaks `rest/AGENTS.md` adaptor pattern (implementation in wrong module, `@Component` instead of `@PSSiteManageBean`, duplicate error envelope, raw `fetch` bypassing CSRF, silent locale-tag fallback).

### 1.3 Locale registration gap

- `modules/perc-distribution-tree/.../cmsTableData.xml:12054-12073` only seeds `RXLOCALE` rows for `en-us` and `es`. `WebUI/src/main/webapp/rxlogin.jsp:83-99` and `WebUI/src/main/ts/login/LoginPage.tsx:150-163` render the dropdown from those rows, so the new locales would be unreachable even after their TMX data is in place. `hi` is referenced in widget XML (`perc.widget.calendar`) and Lucene analyzer but absent from `RXLOCALE` for years.
- `PSTmxDocument.java:545` and `system/src/main/java/com/percussion/i18n/PSI18nStartupManager.java:90-93` show the `Language Tool` regenerates `ResourceBundle.tmx` from `CmsUi/SystemResources` plus `sys_resources/I18n/` plus `rx_resources/I18n/` on startup when `rxlt.properties` says `runAtStartup=true`. The branch extracts `CmsUi/SystemResources/ResourceBundle` to `rxconfig/i18n/` (lowercase), but `PSTmxResourceBundle.MASTER_RESOURCE_FILEPATH` looks under `rxconfig/I18n/ResourceBundle.tmx` (uppercase) and the loader scans `sys_resources/I18n/` and `rx_resources/I18n/` directories. On case-insensitive filesystems both spellings resolve; on case-sensitive ones they would diverge.

## 3. Branch & work plan (rebase-friendly)

> Implementation work happens on a fresh feature branch off `origin/development`. Do not run any of the commands below in this plan phase; the executing agent will run them in implementation mode.

### 3.1 Prep — branch, baseline, regeneration

1. From `origin/development`, create `fix/i18n-inline-locales-and-seed` (no force-push, follow `.kilo/rules/no-force-push-development.md`).
2. `git fetch origin && git checkout -b fix/i18n-inline-locales-and-seed origin/development`.
3. `git status --short` and `git log --oneline -1` to confirm a clean tip.
4. Inspect `PSTmxResourceBundle.processResourceFiles` and `PSTmxDocument.merge` (the runtime merge step) to confirm whether `rxconfig/i18n/*.tmx` (lowercase) is scanned at all. If it is *not*, adjust the load path to scan `rxconfig/i18n/` in addition to the existing `sys_resources/I18n/` and `rx_resources/I18n/` directories (single Java method change, plus a JUnit test).

### 3.4 Commit 3 — Installer and locale registry

- `modules/perc-distribution-tree/src/main/resources/distribution/rxconfig/Installer/data/cmsTableData.xml:12054-12073`:
  - Replace the 2-row `RXLOCALE` seed with 17 rows (en-us through tr-tr). Set `STATUS=1` for all new codes so the login dropdown lists them by default. Include `DISPLAYNAME`, `DESCRIPTION`, and a `SORTORDER` derived from the language family.
  - Add an installer migration step (in `modules/perc-distribution-tree/src/main/resources/distribution/rxconfig/Installer/updateConfiguration.xml` or a new `migration_i18n_locales.xml` ant target invoked from `installDistributionFiles.xml`) that:

### 3.5 Commit 4 — Translation tooling (replaces 20 broken scripts)

- Add `modules/perc-i18n/scripts/i18n_translate.py` (Python 3.10+, cross-platform). Responsibilities:
  - Walk `modules/perc-i18n/src/main/resources/i18n/{CmsUi,SystemResources}.tmx`.
  - For every `tuid` missing a `<tuv xml:lang="<target>">`, shell out to `docker run --rm soimort/translate-shell --brief "<text>" :<target>`.
  - Honor root `AGENTS.md`: 429 / rate-limit detection with exponential backoff (start 2s, double up to 60s, ±20% jitter, max retries), resume from a JSON cache file (`scripts/.cache/i18n_translate.json`) keyed by `hash(text+target)`; do not re-call `trans` for cached entries.
  - Skip translations when `<seg>` matches the placeholder pattern `^\s*\{[0-9]+(,[0-9]+)*\}\s*$` (matches the existing `translate_tmx.py` rule at `update_tmx_limited.py:40`).
  - Validate output before insert: must be valid XML-escapable, must not contain unresolved `&` from unescaped `&amp;`, must not be empty.
  - Provide `--target <lang>`, `--file <tmx>`, `--dry-run`, `--force` flags.
- Add `modules/perc-i18n/scripts/README.md` with usage examples, rate-limit documentation, dependency on Docker `soimort/translate-shell`, and CI notes (the CLI is a developer tool, not a build gate).
- Add `modules/perc-i18n/scripts/test_i18n_translate.py` with the following cases (mocked subprocess, no Docker required):
  - Caches when called twice with the same input.
  - Skips placeholder-only segs.
  - Surfaces rate-limit responses and retries with backoff.
  - Validates output XML escaping before writing back.
  - Operates portably on Windows (Path-based file joins, no `os.path`).

### 3.6 Commit 5 — Runtime locale normalization

- `modules/perc-i18n/src/main/java/com/percussion/i18n/PSTmxResourceBundle.java`:
  - In `addResourcesToCache`, after computing the language key from the header, normalize via `key = key.toLowerCase().replace('_', '-')` so `en_US.tmx`-style tags collapse to `en-us`. (Inline `<tuv>` tags still use the literal `xml:lang` from the canonical TMX, so this only affects the header-derived map key.)
  - In `getKeys`/`getUnit`, attempt the requested language, then fall back to language-only (strip `-<region>`), then `ms_DefaultLanguage`.
  - In `loadResources`, also scan `rxconfig/i18n/*.tmx` (lowercase) in addition to the existing `sys_resources/I18n/` and `rx_resources/I18n/` so the canonical files (which the build extracts to `rxconfig/i18n/`) are loaded.
  - Fix the `I18n` vs `i18n` path mismatch in `MASTER_RESOURCE_FILEPATH` (use the runtime-detected `PathUtils.getRxDir()` lowercased; tested on case-sensitive Linux).
- Add JUnit 5 tests in `modules/perc-i18n/src/test/java/com/percussion/i18n/tmxdom/`:
  - `PSTmxResourceBundleLocaleNormalizationTest`: verifies en_US, en-US, en-us, EN-us all resolve to the same `en-us` bucket; `en-GB` falls back to `en` then default.
  - `PSTmxDocumentInlineMergeTest`: parses a synthetic `rxconfig/i18n/CmsUi.tmx` with 3 languages and asserts the cache has all three.
  - `PSTmxResourceBundleMalformedLanguageTest`: feeds a header with `<prop type="supportedlanguage">EN_US` and confirms the normalized key is `en-us`.
- `WebUI/src/main/webapp/tmx/tmx.jsp`: keep the existing PSRoleUtilities lookup; no changes unless tests demand them.

### 3.7 Commit 6 — Remove REST/WebUI experiment + session default

- Delete `rest/src/main/java/com/percussion/rest/i18n/{I18nResource,I18nAdaptor,II18nAdaptor,Translations,ErrorResponse}.java`.
- Delete `WebUI/src/main/ts/i18n/{api,useTranslations,index}.ts` and any test placeholder. Leave the existing `WebUI/src/main/ts/i18n/message.ts` untouched.
- Delete `ErrorResponse` references from `rest/AGENTS.md` (none exist yet).
- No `rest` POM changes required (no dependency was added).

### 3.8 Commit 7 — Update `perc-i18n/AGENTS.md` and `README.md`

- Add new canonical rules to `modules/perc-i18n/AGENTS.md`:
  - "Inline `<tuv>` is the only supported TMX layout; do not add per-locale sibling files."
  - "Locale tag convention: lowercase hyphen BCP 47 (`en-us`, `es-es`); runtime normalizes on read."
  - "Translation pipeline: `python3 modules/perc-i18n/scripts/i18n_translate.py --target <lang>`; never edit per-key translations by hand without re-running the script (it is the single source of new TUV text)."
  - "Adding a new locale: add `<prop type="supportedlanguage"><code></prop>` to the canonical TMX headers, add a `RXLOCALE` row in `cmsTableData.xml`, add an enum entry in this module's locale list, then run `i18n_translate.py --target <code>`."
- Mirror these rules in `modules/perc-i18n/README.md`.
- Update `modules/perc-i18n/AGENTS.md`'s "Quick Reference" table to reflect the new 17-locale set.

## 6. Definition of done

- `modules/perc-i18n/src/main/resources/i18n/` contains exactly the three canonical TMX files.
- `mvn-env.bat clean install` for `modules/perc-i18n` and `modules/perc-distribution-tree` succeeds with no new warnings.
- New JUnit 5 tests in `modules/perc-i18n/src/test/java/com/percussion/i18n/tmxdom/` pass on Windows and Linux.
- `docker run -i soimort/translate-shell --brief "Hello" :tr` is exercised by `scripts/test_i18n_translate.py` only when Docker is available; otherwise the test uses a mock.
- `rxlogin.jsp` renders 17 locale options and `tmx.jsp` returns translated strings for each of the 17 codes for a sample UI key (`perc.ui.common.label@Change Password`).
- Branch contains a single PR with the seven commits above; Erlang review passes; no per-locale sibling TMX, backup directory, or `__pycache__/` is present.
- Release notes mention: a one-time upgrade migration rewrites `es`→`es` and `hi`→`hi-in`; login dropdown now shows 17 locales; `perc-i18n` translation tool replaces the prior Python scripts.

## 7. Out of scope (will not change in this PR)

- Adding new translation keys to `CmsUi.tmx` / `SystemResources.tmx` (handled in product work, not data cleanup).
- Modifying `WebUI` React screens to use locale-aware copy beyond what the existing `message()` already covers.
- Adding product-level locale picker UI for end users (the existing login form remains the locale selector).
- Tomcat/DTS i18n (separate product; not part of `perc-i18n`).
