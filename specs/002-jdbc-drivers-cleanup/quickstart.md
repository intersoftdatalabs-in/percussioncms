# Quickstart: JDBC Drivers Packaging Cleanup

**Phase**: 1 — Design & Contracts
**Date**: 2026-07-11
**Spec**: [spec.md](./spec.md)
**Branch**: `002-jdbc-drivers-cleanup`

## Purpose

A runnable validation guide that proves the change works end-to-end on a local checkout. Each scenario maps to one or more spec success criteria. The full test task list will be generated by `/speckit.tasks`; this document is the *validation* surface, not the task list.

## Prerequisites

- JDK 21 (per root `AGENTS.md`; the project uses `./mvn-env.sh` / `mvn-env.bat` to enforce this).
- POSIX shell (`sh`) with `unzip`, `stat`, `find`, `grep`, `sed` on PATH (for the new shell assertion and the existing `verify-jdbc-drivers.sh`).
- Working tree on branch `002-jdbc-drivers-cleanup`.

## Scenario 1 — `_jdbc-stage` is not in the shipped JAR (maps to FR-001, SC-001)

After implementing the `<delete dir="${assembly-directory}/_jdbc-stage"/>` step in `installDistributionFiles.xml` immediately after the staged copy:

```bash
cd modules/perc-distribution-tree
../../mvn-env.sh clean package

# Expect: zero matches.
unzip -l target/perc-distribution-tree.jar | grep '_jdbc-stage' && echo "FAIL: _jdbc-stage leaked" || echo "OK: no _jdbc-stage in jar"
```

Expected: `OK: no _jdbc-stage in jar`.

## Scenario 4 — JUnit 5 unit test on the install script's delete set (maps to FR-008, SC-006)

After adding the JUnit 5 test class `src/test/java/com/percussion/distribution/jdbc/InstallXmlDeleteSetTest.java`:

```bash
cd modules/perc-distribution-tree
../../mvn-env.sh test
```

Expected: the new test class runs and passes. Test asserts:
- (a) the install script's delete set contains all 7 bundled-driver filenames (E2 list).
- (b) no `<include name="...">` line in the delete block contains `*` or `?`.
- (c) `mysql-connector-java-9.0.0.jar` and `ojdbc17-99.99.99.99.jar` are not in the delete set.

## Scenario 5 — Shell static assertion wired into Maven `verify` (maps to FR-008, SC-006)

After adding `scripts/check-no-glob-deletes.sh` and wiring it into the Maven `verify` phase:

```bash
cd modules/perc-distribution-tree
../../mvn-env.sh verify
```

Expected: the new shell assertion runs and exits 0. The assertion extracts the `<delete>` block under the `install_jdbc_drivers` target from `install.xml` and asserts no `<include name="...">` line contains a glob character. If a glob is reintroduced in a future change, the assertion fails the build with a clear single-line error.

## Scenario 7 — Integrator-supplied driver is preserved on install (maps to FR-003, FR-004, SC-003, SC-005)

This is a static-check scenario covered by the JUnit test (Scenario 4) and the shell assertion (Scenario 5). A full end-to-end installer run is impractical in CI (requires unpacking a CMS distribution, running the installer against a target install dir, and inspecting the result). The unit test and the shell assertion together prove the property structurally:

- The delete set contains only the 7 exact bundled filenames (E2).
- Therefore, any other JAR in `jetty/base/lib/jdbc/` cannot be matched by the delete and is preserved.

For manual verification outside CI:

```bash
# Build a fresh distribution, unpack it, simulate an upgrade with an integrator driver,
# then run install.xml's install_jdbc_drivers target via ant directly.
cd modules/perc-distribution-tree
../../mvn-env.sh clean package
mkdir -p /tmp/sim-install/jetty/base/lib/jdbc
unzip -j target/perc-distribution-tree.jar 'jetty/base/lib/jdbc/*' -d /tmp/sim-install/jetty/base/lib/jdbc/
# Drop an integrator-supplied driver whose name would match a bundled glob:
cp /path/to/mysql-connector-java-9.0.0.jar /tmp/sim-install/jetty/base/lib/jdbc/
# Run only the install_jdbc_drivers target from install.xml with -Dinstall.dir and -Dinstall.src set:
ant -f src/main/resources/distribution/rxconfig/Installer/install.xml install_jdbc_drivers \
    -Dinstall.dir=/tmp/sim-install -Dinstall.src=/tmp/sim-install -Dcustomer.jdbc.drivers=/tmp/sim-install/jetty/base/lib/jdbc
ls /tmp/sim-install/jetty/base/lib/jdbc/  # expect: the 7 bundled drivers PLUS mysql-connector-java-9.0.0.jar
```

Expected: `mysql-connector-java-9.0.0.jar` is still present after `install_jdbc_drivers` completes.
